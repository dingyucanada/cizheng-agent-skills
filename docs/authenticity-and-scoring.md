# 多张实物照片 → 可回查的 AI 研判报告

瓷证把报告中的三件事分开：**照片上看到了什么、为什么形成某项归属意见、这个意见还缺什么证据**。本轮最多选用八张原照；档案其余照片仍保存，但不被算成已观察。报告按照片列出区域坐标、可见细节、解释和限制，再按制作时期、窑口、装饰风格列出候选、理由、支持观察、冲突观察及竞争解释。原照 SHA256、实际阅读的资料段落及版本一同保存。

这里的“AI 研判报告”是照片辅助研究。生成报告本身不证明器物为某年代原作，也不认证来源、交易或所有权。专家可以按图核对，再登记复核或订正。人工登记不覆盖模型原意见。

## 当前实际可用的数字

**采集覆盖指数 = 本轮原照中已标记的通用视角类别数 ÷ 5 × 100。** 五类为器身全貌、底足与露胎、口沿与内壁、釉面细节、纹饰细节。同类照片重复不增加类别数；档案中的未选照片不增加本轮得分。款识、损伤与修复可另行标记，但不擅自作为所有器物都必须存在的特征。

这个指数是采集进度，依据上传者的结构化视角声明计算。系统不从文件名猜视角，也不把视角标记视为画面认证。五类通用提示不是已验证的断代清单，具体器型应由专家调整；100分也可能是一组清晰的仿品照片。旧版本没有标记时得分为0，表示标记缺失，不能据此判图像无效。

另显示“有模型区域观察记录的原照数 / 本轮选图数”。只计本案照片，不拿馆藏参照图补足。观察数量不能代表观察正确；无记录或运行失败时不会伪装为完成报告。每个指标绑定 run_id、input_hash、资料版本和 `photo-evidence-coverage-v1` 算法版本。后来改视角、补图或改编目，不会改写旧报告。

## 为什么暂不提供一个看似精确的“真品率”

当前 JSON 的 `authenticity_probability.value` 为 `null`，状态为 `not_calibrated`；界面显示“待校准”。没有陶瓷领域的专家真值与独立校准测试，模型自报93%或路由器输出0.93，都不足以把数字解释为器物为真的概率。神经网络的准确率与概率校准是不同问题，已有研究也展示了过度自信及校准方法。[Guo 等：On Calibration of Modern Neural Networks](https://proceedings.mlr.press/v70/guo17a.html)

将来需要先定义判定目标，例如“符合所声明的某时期某窑口原作”，再收集该范围内的可信真值、仿品、难例与无法判定样本。按器物和来源分组，隔离训练、校准、最终测试，避免同一件器物的不同照片分散到各集合。比较 Brier 分数、可靠性曲线、校准误差、拒判后的覆盖率及错误代价；报告样本量、适用范围、置信区间和模型版本。无法判定样本不能简单当作赝品。照片不能解决的问题仍需要实物检查或检测证据。少量专家案例适合检查流程和解释质量，不能宣称建立了可信总体概率。

## Jev、Laya 的位置

Jev 的模型调用接收页面文字、元素与操作历史，输出浏览器操作和目标选择；其分布不是陶瓷图像鉴定分布。它可作为公开资料采集的候选工具，本期不把它接成真伪检测器。[Jev 实际模型调用源码](https://github.com/browser-use/jev-ultrafast/blob/main/jev_ultrafast/model.py)

Laya 提供文本上的类型化选择、评分和是非决策，并支持领域训练与校准。它没有提供可直接用于本案照片的陶瓷真值模型。瓷证已保留本地文字“影子路由”实验入口：只记录建议和分布，不改变正式路由、不跳过人工复核，也不转成真品概率。当前协议测试使用明确标记的替身；尚未完成真实 Laya checkpoint 的本案实测。[Laya 官方仓库](https://github.com/NandhaKishorM/laya)

## 使用流程

1. 建立案件，填写待核查归属与来源声明，按用途选择博物馆、收藏或拍品研究。
2. 保存一组原照，可分组标记视角；在图像研究中为已有照片补标记。选择本轮最多八张关键照片。
3. 连接 Spark 本地视觉服务后开始研判；模型先实际读图、按需查看局部，再检索及阅读资料，形成带理由的意见。
4. 回查每一项观察与引用，处理优先补证；经批准的公开或脱敏文字可交 StepFun 提出反证，再由本地模型结合图像修订。
5. 登记复核，导出 JSON、Markdown 和可独立打开的 HTML 报告。原图、指标口径、理由及限制一起交接。

公开 GitHub Pages 体验使用预先编写的教学案例，不执行模型推理。实时 AI 报告由私有后端执行；教学体验、协议测试、实际模型运行及专家验证分别记录，不能相互替代。
