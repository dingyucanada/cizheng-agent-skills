# 从鉴定按钮到陶瓷证据研究工作台：瓷证的开发记录

本篇尚未发布。官方“十日谈”是赛事栏目名，不表示项目已经开发十天；本文只记录实际完成的本机研究、设计、开发和检查。Spark、真实模型与专业专家验收没有发生的部分不写成成果。

## 业务决定结构

最初方案围绕轻量预审和大模型陶瓷鉴定。研究 Jev 与 Laya 后，我们没有把浏览器智能体或文字路由框架当作本地视觉识别权重，也没有继续承诺原生真伪、AI生成概率。图片清晰、知识检索有出处和模型输出自信，都不能自动证明器物真实。

专业用户的问题比“这是什么年代”更具体。博物馆需要登记对象、核对文献和状况，收藏者需要整理来源凭据，拍卖图录需要区分归属措辞和物理状况。实际阅读 MuseumPlus 产品册、Artlogic 官方工作流、Christie’s 和 Sotheby’s 说明，以及 Getty CDWA 来源史规范后，我们把对象记录、可见现象、材料记载和归属意见分开。没有登录同行客户后台，没有访谈这些机构，也不把产品宣传当成使用测试。

新版采用六个工作区：案件总览、器物档案、图像研究、知识资料库、研判与补证、报告复核。深色导航、浅色研究桌和证据检查器让当前任务与旁证同时可见。原照底片带、双图、缩放和人工区域记录用于真图操作，不画假的AI热点。三个角色改变采集与交付重点，不能被当作机构身份。

## RAG与Skills各自承担什么

知识库保存可回查的出处和正文，Skill保存执行方法与适用边界。25条项目资料是项目原创短摘要，参考 V&A、CCI、Getty、Met 和特定版本拍卖术语。它们不是完整陶瓷断代库，未经过原机构或专家审定。未知文字权利只登记出处，不能自动抓整本书或把全部官网文章视为开放许可。

本地 SQLite 索引支持中文重叠双字词，检索分是文字相关性，不是可靠性。运行开始时固定资料快照，真正引用还要经过读取段落与版本、文档哈希、段落哈希和locator校验。公开馆藏的时期标签只属于该编号对象，不成为未知器物的答案。

七个自研Skill包按描述、正文、参考资源渐进加载。通用编目与来源核查加入原先的器类路由、青花花觚比较、状况假说和补证修订；每个包有整包哈希和真实审核状态。我们学习官方材料中工具、方法和运行框架的分工，不伪造NVIDIA Verified或专家签名。

## 可交接的材料工作

没有视觉模型也应能工作。原照归档、区域人工观察、已获许可文字、来源事件和状况检查都可以独立登记。来源事件区分上拍、出版、展览、流转和缺口，保存每项记载与本器物的联系依据。“有凭据定位”只表示资料可找回，不证明历史事件发生。PDF保留原文件和目录，尚未OCR。许可TXT可在文字凭据任务中分段读取，引用必须对应实际已读回执；附件中的文字始终作为待核查材料，不作为系统指令。

准备档案输出JSON、Markdown和可打印HTML，保留图像哈希、来源版本、记录限制和人工复核。准备资料复核绑定案卷版本，模型意见复核绑定已完成运行；两者分别保留，更改材料后旧复核过期。单人本机操作人的身份没有认证，不能直接变成机构审批。

## 反例比评分有用

真实浏览器验收发现，初始化早于选案的知识列表会错误禁用关联按钮；修复让按钮随当前案更新，不丢检索上下文。独立初审还复现了更严重的问题：来源库改到r2后，仍为同一案卷版本导出的准备档案悄悄读取r2。这个初版被硬门槛拒绝，而不是靠其他优点抵消。修订后按实际显示的文档revision/hash关联，显式更新才推进案卷；可变的全库索引信息也不混入固定材料包哈希。

另一个反例是可读准备档案只展示资料前四段，命中的后续段落会消失。现在完整输出已关联授权段落及校验标识，并与JSON核对。所有工程测试、失败反例与版本记录保留；纯色图、脚本模型和模拟网络只能证明协议，不能算陶瓷鉴定样本。

## 仍需真实平台与专业验证

Spark承担原图视觉推理，StepFun只看公开或明确批准脱敏的文字，批准包先固定、再单次提交，不自动重试。真实本地模型接通后，还要做实际图像/局部/规划行为探针，冻结同模型、同资料、同预算的有无Skills对照，再由专家看图片和报告。3–5件专家样本是个案验证，不能据此声称行业准确率或保证获奖。

当前成果是受控试用的证据研究工作台；机构多用户权限、可信签署、实物检查、专业质量、实际Spark优化和赛事视频仍需完成。设计细节、权威来源和引用边界保存在 professional-research.md，部署准备在 spark-validation.md。这些边界也是后续验证的任务清单。

本轮新增无图文字凭据核查：只引用成功主动作实际接收的有限片段，正文回执另存字符范围和SHA；PDF不OCR。准备档案与离线交接包含历史事件所用旧版段落、原始照片与原文件清单；库中其它案卷与资料不进入交接。所有工程协议测试仍使用明示的合成夹具，不能推导专业鉴定成绩。

## 让首次体验真正完整

后续试用指出一个产品问题：评审打开系统后，如果还要自己找图片、上传多项材料、编写题目和关联资料，看到的只是待填表单，无法理解研究流程。我们因此准备了三套 Met 公开教学案，配齐实际照片、馆藏出处、项目原创文字说明、观察示例与补证路径，提供免上传的浏览器体验和本地完整教学导入。

教学材料与实时 AI 保持清楚区分。预写的意见标为项目编写的研究示例，浏览器实际完成编辑、证据定位、补证比较、复核备注和导出；它没有请求模型，不能剪成实时推理演示。GitHub Pages 只发布公开的 `site/`，真正的 Python 工具执行、私人材料和模型请求由本地 / Spark 后端完成。首次体验不依赖服务在线，实际推理仍必须凭真实运行证明。

公开仓库将 README、七个方法包、来源权利、部署和工程验证整理成一个入口，并按官方六项评分列出可核查证据。Spark / StepFun 实测、专家样本、B 站视频、真实合影和正式表单仍作为待完成任务；完整教学网页不能替代这些材料。本篇仍是草稿，平台公开发表之后才有征文 URL。
