# 专业陶瓷证据研判工作台：一手研究与设计约束

核实日期：2026-09-28。对象：博物馆研究与藏品人员、私人收藏者、拍卖行专家。此报告只证明公开资料中所见的流程与术语，不证明当前应用具备专业鉴定能力。所有模型与 Spark 均未接入；本次没有专业用户效果数据。

## 先落实的五条约束

1. 以对象记录为中心。调查 case 与永久馆藏/库存编号分开；图像、文献、来源事件、状况检查、归属意见都连接到对象，而不是散落在聊天消息里。
2. 编目、状况、来源链、归属与鉴定分别表达。状况记录描述物理状态；来源链描述持有与转移；归属是年代、窑口、作者等意见；单张照片观察不得自动升级为真伪定论。
3. 每条观察可回到证据。保留图像编号、部位、观察方式、检查日期与记录人；缺少足底、口沿、比例尺、修复历史或来源文件时，呈现具体缺口。
4. 工作台支持批量检索与逐条核对。列表筛选、记录预览、分区编辑、相关记录跳转、修改历史比全屏聊天更符合公开专业流程。比较视图必须同时显示来源与不可比较项。
5. 馆藏页是机构对那件藏品的记录，不是上传器物的答案。参照年代与术语可被检索，但不能据此宣称用户器物同代、同窑或真实；缺口不能变成虚假的精确置信度。

上述为本项目的设计建议。下面将事实观察与项目推断分开列出。

项目推断：图片、对象记录和文献说明应同时可用；比较时显示比例与视角是否兼容。基准记录应保存来源、对象编号、获取日期和版本，允许日后修订。图像相关性不等于年代、窑口一致；本案器物与基准对象之间需要单独的比较说明。

## 必须区分的五种工作对象

| 工作对象 | 回答的问题 | 应保存的内容 | 不能自动推出 |
|---|---|---|---|
| Catalog record／编目记录 | 这是什么对象，怎样描述和找到它？ | 编号、器形、材料/技术、尺寸、题识转录、图像、描述、关联记录；可含有明确标注来源的机构归属 | 编目字段填满不等于鉴定完成 |
| Condition／状况与检查 | 某时点、某检查方式下，哪些物理状态被观察到？ | 检查日期、观察人、照明/仪器、部位、损伤/补配、证据图、未检区域、处理史 | 裂纹、包浆、修补或完好程度不能独立确定年代或真伪 |
| Provenance／来源与收藏史 | 何时由谁持有、通过何种事件转移？ | 所有人/保管人/代理角色、地点、日期区间、交易/继承/入藏事件、文件、缺口与不确定性 | 口述或一张旧标签不能自动证明完整来源链或合法所有权 |
| Attribution／归属意见 | 哪个年代、窑口、作者或类型更可支持？ | 提出者、日期、限定措辞、支持/反驳证据、参照物、替代解释、未决问题 | 机构或专家意见不是永恒事实；“某窑型”不能转为确切产地 |
| Authentication／鉴定判断 | 对指定真伪问题，检查范围内能形成何种专业结论？ | 委托范围、方法、实物/技术检查、人员资质、结果与限制、审核和报告版本 | 视觉相似、资料命中、款识读对或模型分数不能替代实际鉴定 |

## 可以实施的专业流程与核心交互

1. **建案与范围**：选择研究问题（编目补全、状况核对、来源文件整理、年代/窑口候选比较）；区分对象编号、调查编号与委托说明。状态由实有操作更新，不预填“专家已审核”。
2. **证据接收**：保存原始照片和文件；照片标整体/口沿/内壁/足底/款识/细节，记录尺寸和照明信息。缺项提示应对准研究问题；不是所有 case 都要求相同附件。
3. **证据台**：缩略图列与大图检查器；缩放、旋转、图像编号、区域标注。标注可以创建“观察”，也可以创建“待核问题”；不能默认是一条模型检测结果。
4. **参照比较**：双图或三图并排，显示对象来源、部位、比例尺和视角；同一行比较器形、足部、胎釉、纹饰、款识、技术。用户写入一致点、差异点与不可比较点，再引用来源卡。
5. **假设与证据**：不同年代/窑口假设并列；区分直接观察、文件陈述、机构记录与本案推断。支持、反驳、无关和未决四种关系，比“真品概率 96%”更适合当前系统能力。
6. **状况与来源**：状况按部位列表并连接图像；来源按时间线保存事件和文件。来源未知跨度用空白/虚线和文字呈现，不制造连续链。实物复核、UV 或材料分析仅可作为待办，并记录由谁执行。
7. **审阅与交付**：摘要含研究范围、已获证据、候选解释、未决问题和建议下一步；附图像清单、引用、来源链和修改记录。保存可回到档案的报告快照；真实审核人和时间存在后才显示署名。

推荐默认桌面布局：紧凑案件/对象队列、宽证据检查区、可收起的记录与判断区。底部或侧栏放证据引用，不用仪表盘大数字占据主要空间。中性色与低饱和状态色帮助长时间检查；较大的图像区域和等宽编号支持资料核对。此为原创项目推断，不是声称竞品已经采用同一布局。

## 已核实种子及接入规则

九条候选种子保存在同目录 [knowledge-seeds.json](../knowledge/source-provenance.json)。每条都有直接支持的问题、原创短摘要、范围、局限与权利说明。它们是资料检索和人工记录的种子，不是鉴定规则库，也不是任意器物的标签真值。

接入前保持三个约束：一是来源相同的摘要不能被算成独立交叉验证；二是基准对象标签只描述基准对象，本案需建立独立证据链；三是未经真实模型调用、专业实物复核或用户试验，不宣称智能识别、准确率或专业效果。当前可以真实交付的能力是档案整理、图像标注、限定资料检索、可引用比较与报告留痕。
