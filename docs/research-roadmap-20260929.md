# 研究路线：专家纠错、机构联合训练与受控采集箱

日期：2026-09-29。本文是拟议研究方案，供机构、专家与工程人员逐项审查。**当前未部署 NVIDIA FLARE 联合训练、奖励模型训练或自动在线强化学习，未制造或验收桌面采集箱。** 现有工程测试与公开案例不能代替专家样本验证。照片支持观察和归属研究，不能独立证明烧造年代；实物检查、来源档案及适用的检测证据仍需分别评价。

## 从现有接口出发

| 已实现入口 | 可以沿用的材料与行为 | 研究时仍需补齐 |
| --- | --- | --- |
| `POST /api/cases/{id}/capture-sessions`、`GET .../capture-sessions` | 本案有界会话、设备声明、到期时间与预算 | 真实相机控制、设备配对与机构权限均未实现；`desktop_box` 是设备类别声明 |
| `POST /api/cases/{id}/device-captures` | 一个 metadata JSON 和一个 JPEG/PNG；实际字节 SHA、原件、视角、采集与接收时间、回执留档 | 灯光程序、色卡批次、曝光、镜头与夹具位置需另设机构本地采集清单；当前严格 schema 不接受任意新增字段 |
| `POST /api/cases/{id}/annotations` | 人工区域坐标和观察可绑定照片 | 专家身份、逐项标注复审及训练许可需独立核实 |
| `POST /api/cases/{id}/corrections`、`POST .../reviews` | 关联本案已完成 run，记录依据及 image/in_person/document 复核方式，保留原意见和订正历史 | 目前 `identity_verified=false`；登记为 reviewed 不等于可信专家签署，更不是可直接训练的真值 |
| `GET /api/cases/{id}/risk-triage`、`POST .../risk-facts`、`POST .../risk-checks` | 比较有定位凭据的结构化记载、追加补正、列出下一项补证 | 固定权重尚未专家校准；颜色、像素和传感器读数不自动转成真伪或年代规则 |
| `GET /api/cases/{id}/opinions/preview`、`POST .../exports`、`GET /api/artifacts/{id}` | 导出冻结案卷、原图、模型意见与复核记录，供本地审核 | 完整导出可能含原图和身份资料，不能直接充当联邦消息或公开训练集 |
| `python -m cizheng.paired_eval` | 固定材料、有/无 Skills 两臂、随机报告编号与评阅者隐藏映射 | 这是评测入口；尚无训练、联邦或候选模型发布 API |

以上入口沿用本机可信操作者、会话令牌、TrustedHost、Origin、案件版本与幂等约束，**不是机构多用户授权系统**。机构节点应读取获准的本地冻结副本，不应把工作台改成公网服务或把本机会话令牌用于联邦身份。[采集协议](device-capture.md)、[风险公式](risk-triage.md)、[现有订正实现](../cizheng/store.py)、[API](../cizheng/api.py)。

## 先把专家反馈变成可核查材料

首批沿用 3–5 件独立器物的探索试验，逐件检查观察和论证。这个数量用于核对流程与错因，不能据此认定训练充分或报告行业准确率。证据包与专家标签包分开：首轮模型只看获准证据和问题，标签、专家结论与身份不进入 prompt、RAG 或 Skill。[专家接入](expert-validation-intake.md)、[盲评准备](expert-intake.md)、[评测协议](../evals/PROTOCOL.md)。

拟新增的是**机构本地离线审核清单**，本轮没有实现其服务。每条记录至少包含：

- 机构内稳定 `object_id`、冻结案卷版本、原图 SHA、run_id、报告版本，以及具体照片区域或资料段落定位。
- 原始模型输出、专家订正、订正依据、错误类别、可从照片判断的范围、争议和未知。区分“观察错误”“引用不支持”“遗漏冲突”“超出照片边界”，不把最后的归属标签当作全部反馈。
- 评阅者身份核实记录、复核方式、时间、第二次审核或争议处理；单人意见如实标明，分歧不强制改成一致答案。
- 许可的具体用途：本地研究、训练、机构间参数交换和模型分发分别登记；明确保留期限、退出处理和授权范围。获准本地看图不自动等于获准训练或发布。
- 分组、数据版本、审核状态和排除理由。专家标签与公开训练示例分别管理；价格、所有者与联系人资料不作为训练特征。

现有 corrections 字段只有订正正文、依据和关联 run，需经上述审核才能形成训练例。专家反馈**不会直接更新生产模型**；审核、训练、评测与发布是四个独立环节。

## 模型研究的顺序与交付物

| 阶段 | 拟做的实验 | 可以进入下一阶段的证据 |
| --- | --- | --- |
| 1. 冻结基线与纠错集 | 先完成隐藏标签的个案盲评；区分资料/采集问题、方法问题和模型错误。方法与提示修订作为独立候选保存 | 许可、器物分组、原始评语、失败记录、固定模型/资料/预算与可复跑基线齐全 |
| 2. 本地离线监督微调 | 先研究文字 LoRA：给定已核验观察及实际资料段落，学习有依据的理由、竞争解释和补证；冻结视觉模型。若以后训练视觉模型，另验收图像区域与训练适配 | 保存训练清单、基座/分词器/adapter 哈希、配置与资源实测；和基线比较保留集的观察支持、引用支持、拒判及流程错误 |
| 3. 机构联合训练 | 本地训练已可重复后，先用获准公开材料模拟 2–3 个站点，再考虑真实机构各自在本地训练并仅交换获准参数和汇总指标 | 模拟结果与真实机构结果分列；网络/过滤/撤销测试通过；跨站评估显示逐机构表现，且没有掩盖任何机构或关键错误组的退步 |
| 4. 可选偏好/奖励模型 | 有足够且一致的专家偏好后，先在相同证据和问题下比较两份回答，训练离线质量排序候选；另测排序与专家判断的一致性 | 独立偏好保留集、评阅分歧、反例和跨机构评估齐全；模型不能靠篇幅、肯定语气、身份或隐藏答案取得高分 |
| 5. 可选后训练与候选发布 | 只有奖励模型有效且资源/模型适配验收后，才单独研究 NeMo RL 离线后训练；训练阶段的生成与奖励计算不接生产反馈流 | 候选先在影子环境复跑，固定业务预算和导出行为；专业评阅与工程回归均通过，再由责任人批准版本切换并保留回滚版本 |

NVIDIA 的 [FLARE HuggingFace SFT/PEFT 示例](https://github.com/NVIDIA/NVFlare/tree/main/examples/advanced/llm_hf) 展示了 LoRA 与 adapter 参数交换，可作为第 3 阶段的实现依据。它不是当前 Qwen3-VL、GB10/ARM 或瓷证任务的兼容性证明；模型加载、可训练模块、精度和显存都需要单独实测。联邦路线与奖励模型路线分别验收，不同时改变采集、基座、资料和训练方法。

[NeMo RL 奖励模型文档](https://docs.nvidia.com/nemo/rl/latest/guides/rm.html) 给出成对偏好与奖励模型作为后训练环境的流程。本项目拟先验证“回答质量排序”，再研究政策模型优化；通用奖励模型的分数、风险优先指数和采集覆盖指数都不能充当器物真值或烧造年代奖励。

## 原图留在机构内的 FLARE 方案

拟议结构为各机构的本地训练节点加独立联邦协调服务。**现有工作台 API 与未来 FLARE 通道分别管理**：案卷回执属于本地业务证据；联邦 job 负责获准候选参数的收发，不读取生产工作台原图接口。

| 数据或操作 | 拟议流向 | 权限与可审查证据 |
| --- | --- | --- |
| 原图、标签包、专家身份、单器物错误明细 | 留在所属机构的受控存储和本地训练/评测进程 | 机构决定读取权限；本地访问日志、清单哈希与授权记录，不发送图片、裁剪、图像 embedding 或逐样本日志 |
| 基座和训练 job | 获准模型副本在机构内；协调端分发已审核的配置/候选 adapter | 固定基座、分词器、schema、adapter 模块/rank/scaling、job 和训练代码哈希；机构管理员批准任务，拒绝未审核自定义代码及原图导出任务 |
| 本地更新 | 机构节点经结果过滤发送允许的 adapter 参数；协调端聚合并持久化候选 | 参数键/形状/类型白名单、有限值与大小校验；拒绝任意附件、文件路径、文本和隐藏附带数据。相同格式只是前提，聚合方法还需验证，不把任意 LoRA 合并当作有效训练 |
| 评测 | 模型到机构，机构在本地保留集运行；协调端仅收获准汇总 | 记录按器物计的组样本数、失败/拒判及误差区间；小组结果抑制或延迟发布，防止反推单器物身份 |
| 暂停、退出与发布 | 机构可拒绝任务；协调端中止轮次并隔离异常更新；发布另行批准 | 缺站、断线、撤销身份、过期 job、错误版本演练；退出后的模型贡献不能承诺已被删除，应按约定隔离或重训并说明影响 |

FLARE 的 [架构文档](https://nvflare.readthedocs.io/en/main/system_architecture/system_architecture.html) 区分 Simulator、POC 和生产部署。公开数据模拟只验证流程；真实机构试点须独立配置 PKI/mTLS、角色授权、机构策略、网络出口限制和审计，不能将无安全保证的模拟环境当作机构网络。机构仅批准需要的协调端地址和任务能力，生产推理和训练资源也应分离。[官方安全概览](https://nvidia.github.io/NVFlare/security/)。

原图不出机构是数据流设计，**不等于参数或模型不会泄漏资料**。拟议实验需审查更新重建、成员推断、恶意/异常更新与小组汇总泄漏；根据威胁模型选择并验证裁剪、差分隐私或保护聚合的方案，预登记隐私预算与会计方法。mTLS 保护传输，不单独解决这些风险。FLARE 的 [Filters](https://nvflare.readthedocs.io/en/2.9.0/programming_guide/filters.html) 可用于任务/结果过滤及隐私处理；具体过滤配置、数据种类、阻断与审计均需实测，列出技术名称不能代替验收。

第一个算法候选可从统一 adapter 配置的 FedAvg 起步，登记每站训练步数、按独立器物计的贡献量和权重上限；保存本地候选与联邦候选，防止大站覆盖小站表现。后续选择算法的依据是机构差异与逐组结果，而非增加技术名目。[FLARE 跨站评估](https://nvflare.readthedocs.io/en/2.9.0/programming_guide/controllers/cross_site_model_evaluation.html) 支持将模型送到各站本地验证并汇总矩阵；本项目拟用它比较本地与全局候选，不上传评测原图。

## 采集箱原型：先验证重复性

拟议桌面采集箱用于保存**同条件可比较的多视角图像**。器物支撑、摆放与翻转由机构人员决定；相机/灯光控制器未来通过受信的本机桥接输出文件，继续使用现有 capture 会话。自动转台、品牌 SDK、镜头标定与设备认证均需后续原型验证。

| 部分 | 拟议采集记录 | 验收方式与现有接口映射 |
| --- | --- | --- |
| 多视角 | 每轮选 6–8 张关键原图：全貌、底足、口沿/内壁、釉面、纹饰，以及确实存在的款识/状况部位；记录相机位置、视角和物件朝向 | 同器物、同条件重复 3 次，复核相同部位可对应；上传 `capture_role` 和 `view`，人工核对标签。标签仍不是画面认证 |
| 光照 | 保留漫射光基准；掠射光用于表面起伏与反光对照，独立记录灯位、照度和曝光。可选偏振须保留普通光对照及偏振方向 | 锁定可重复设置，检查高光遮蔽、阴影与细节损失；照度 `lux` 等可在 sensors 登记，光源程序/批次存本地采集清单 |
| 色卡 | 记录色卡型号、批次、参考值、位置、镜头/相机和色彩处理版本；同一轮采集保留校验帧 | 比较校验帧的颜色偏差与重复性，事前约定本设备阈值。图像衍生处理另存且保留来源；不以“放了色卡”宣称色彩已校准 |
| 尺规 | 比例尺与被测区域尽量同平面，保留摆放图及测法；器物实际尺寸由可回查的测量记录提供 | 先用已知尺寸目标验证透视/镜头误差和重复测量范围。单张尺规照片不证明曲面、倾斜部位或整体高度可精确测得；人工转录尺寸进入有依据的 risk-facts |
| 可选显微 | 记录倍率、工作距离、照明、标尺/标定日期与整体图的区域对应；保留原始显微图 | 每种倍率单独校准像素到长度；没有对应与校准的细节只作局部观察，不据此直接断代 |
| 可选传感器/仪器 | 记录读数、单位、方法、设备/校准证据与原始结果；光谱等多维数据另用专门清单与格式 | 当前 sensors 只登记有限数值及 `unknown/operator_declared/documented_not_verified`；没有“已核验校准”状态，也不执行仪器推断。仪器接入、参考材料、误差与专业解释另行验收 |

[FADGI 2023 指南入口](https://www.digitizationguidelines.gov/guidelines/digitize-technical.html) 强调参考目标、测试软件与持续质量监测。此处借鉴其质量管理原则；瓷器曲面、反光与三维测量需要本项目验证，本文不声称 FADGI 等级或实验室检测认证。

当前每会话最多 8 张/80 MiB/1 小时，默认 8 张/40 MiB/15 分钟；每案最多 30 张原照，本轮分析最多 8 张。重复采集与校验帧须按预算分组归档，模型只看明确选定的关键图；跨案的同器物仍在研究清单中归为同一 `object_id`，不能扩大独立样本数。单图 JPEG/PNG ≤20 MiB、≤40 MP，metadata ≤16 KiB。[真实采集实现](../cizheng/device_capture.py)、[独立客户端](../scripts/device-capture-client.py)。

相机 RAW/TIFF 先保存在机构采集库，当前桥接上传 JPEG/PNG。采集清单应记录源文件与衍生文件的各自 SHA、转换参数和对应关系；接口的 `original_sha256` 核对的是**实际上传的 JPEG/PNG 字节**，不能冒称已归档或验证 RAW。回执保留 `clock_verified=false`、`vendor_authenticated=false`、`sensor_inference_performed=false`，直到对应能力单独实现与验收。

## 实验分组与停止条件

1. **先划分器物，再划分数据。** 同器物的全貌、局部、裁剪、重复拍摄、修复前后、同来源记录与派生回答一起分组；跨机构同器物也不能落入两侧。身份映射留在机构内，跨站重复核查方法另经授权。训练/开发、偏好训练、校准与最终盲测清单分别冻结。
2. **分开报告适用范围。** 时期/窑口/器型、修复与后配、易混后仿、证据不足、来源可靠程度、相机与光照条件均记录分组和样本数。用留出机构/来源检查外部分布；无法判断保留为无法判断，不当作赝品硬标签。
3. **比较具体错误。** 按器物统计区域观察错误、引用不支持、重要冲突遗漏、无依据归属、欠证时确定回答、拒判覆盖与补证可用性，同时保留失败、资源成本和端到端耗时。固定模型/资料/预算做比较；只看总均分或训练 loss 不能发布候选。
4. **采集改善单独证明。** 原型先报告色卡偏差、曝光遮蔽、尺度误差、重复性、视角对应与哈希回取。再在同器物盲评中比较专家是否更容易核对观察、模型是否少遗漏；清晰度或覆盖指数上升不能代替归属质量改善。
5. **有退步或证据缺口就停在研究环境。** 未授权用途、无法核实专家依据、跨集合泄漏、异常联邦更新、专业关键错误组退步或工程回归失败，均保留失败并停止切换。推广范围与通过阈值在实验前登记，不根据结果临时改变；测试集用于最终报告后不继续充当调参集。

真品概率继续保持 `null/not_calibrated`。即使未来某任务达到可接受的专家评价，概率也需要另行定义目标器物群、可信标注、校准集、可靠性/Brier 等检验及范围外拒判。风险六维固定分母和采集覆盖公式保持其工作排序/进度用途，研究候选无权自动改写。[数字口径](authenticity-and-scoring.md)。

每次研究的最低交付物为：用途许可与样本分组清单、冻结输入哈希、原始专家评语、基线与候选版本、逐组评测及失败、采集/联邦日志、资源记录和发布/回滚决定。原图和标签继续作为机构私有材料；对外仅发布另获许可的脱敏汇总。本轮交付本文，不包含训练权重、FLARE 网络、硬件验收或新增专业成绩。
