# 瓷证项目说明

[仓库主页](../README.md) · [部署指南](deployment-guide.md) · [技术栈清单](technology-stack.md) · [完整图文报告书](https://dingyucanada.github.io/cizheng-agent-skills/report.html)

瓷证 CIZHENG 是面向博物馆、收藏档案和拍卖图录准备的陶瓷证据研究 Agent。它把一组实物照片、器物登记、来源文件、专业资料与每一次判断连接成可交接的案卷。作品交付包括可运行前后端、七个领域 Agent Skills、公开教学体验、Spark 部署及验证代码、图文报告和场景演示。当前后端版本为 **0.7.0**；文档和素材迭代编号独立于应用版本。

## 一、业务问题与作品特点

从业者研究陶瓷时，不仅需要一个年代或窑口标签，还要核查观察来自哪张照片、文献说明了什么、来源材料是否对应同一器物、不同评价维度为何发生矛盾，以及新材料如何改变旧判断。散落在聊天记录里的答案不容易复核和交接。瓷证围绕这些工作设计，让原件、定位、证据和分项理由留在同一案卷。

博物馆场景以编目和研究为主：区分馆藏记载与图像观察，核对器形、纹饰、部位和资料出处，并记录下一次采集需要补充的角度。收藏档案场景以来源和历次观察为主：逐项整理来源事件、凭据及同器对应，避免把卖家叙述当成独立材料。拍卖图录场景以描述与交接为主：核对归属理由、状况措辞和附件，输出可复核的图文档案。

作品的第一项特点是**从照片到理由的关联**。用户登记器形、尺寸、款识、来源和状况，查看整体及局部原图，框选观察区域。视觉模型处理本轮照片，生成带图像关联的观察；制作时期、窑口和风格分别形成候选，并列出支持、冲突、缺失与竞争解释。某个维度有支持，不会自动放行另外两个维度。

第二项特点是**固定版本的资料使用**。RAG 主流程采用本案许可的固定资料版本，检索后必须读取实际正文。文档编号、版本、SHA、段落与定位绑定本轮成功读取回执，再进入意见。NeMo Agent Toolkit 在独立离线环境核对引用身份。这样复核者可以找回当时依据的确切材料，而不是仅看到搜索排名或一个似是而非的链接。

第三项特点是**可执行的研究方法**。七个 Agent Skills 覆盖任务与补拍路由、陶瓷编目、青花比较、状况竞争解释、来源、文字凭据及补证修订。方法文件写明适用范围、工具步骤、失败处理和参考资源；宿主按需加载描述、正文和资源，记录整包 SHA，并执行权限、预算与证据合同。Skill 引导下一步研究，领域模型仍负责观察和有限判断。

第四项特点是**先筛查、再深入研究**。六维筛查比较制作时期、窑口、风格、来源、状况与采集中的结构化记载，先指出年份区间、高度、身份及事件顺序矛盾。矛盾指数、已评覆盖和复核优先指数分别显示；未知不被当作相符。数字服务于安排复核工作，不是真品概率或经过校准的 AI 置信度。

第五项特点是**补证改变意见有记录**。批准公开或脱敏文字进入 StepFun 反证审查，返回问题后，本地模型重新看本轮原图、逐项回应并修订。新照片、资料变化和材料修正都会影响旧依据资格；历史观点、文件身份和修改经过保留，避免旧意见被误用。最终由从业者准备人工复核与交接。

## 二、技术实现与架构

![瓷证中文系统架构](../site/report-assets/product-architecture-v09.svg)

| 层级 | 实际实现 | 输出与责任 |
|---|---|---|
| 采集与材料登记 | 浏览器工作台、受控 multipart 采集会话、Python 客户端 | 保留照片、视角、原字节 SHA 与器物登记；品牌设备 SDK 后续适配 |
| 案卷与任务宿主 | Python / FastAPI、SQLite、本案版本、预算和工具注册 | 管理工具调用、原件、资料许可、运行记录与修订资格 |
| 研究方法 | 七个自研 `SKILL.md` 包和 `references/` | 渐进加载；按任务读取方法；记录实际整包身份 |
| 视觉研究 | Spark / GB10 / CUDA、Qwen3-VL-8B BF16 | 双图及局部观察、时期 / 窑口 / 风格分项理由、补证修订 |
| 资料与核查 | SQLite 固定正文、NVIDIA NeMo Agent Toolkit | 检索后读正文；核对引用身份，不据身份核查判定结论正确 |
| 文字协作 | StepFun `step-3.7-flash` | 只接收用户批准的公开或脱敏文字，提出反证问题；原图保留本地 |
| 独立服务 | NIM:8007、TensorRT-LLM:8006、Embedding＋cuVS:8003 | 已各自部署并留证；接入主流程前继续做业务评估 |
| 复核与交接 | 图文报告、逐项理由、材料清单、JSON / Markdown / HTML / ZIP | 汇总实际结果、引用和待补证，保留人工复核入口 |

主工作流为：**登记器物 → 选择照片与任务 → 加载适用方法 → 查看原图及局部 → 阅读固定资料正文 → 分项研究意见 → 引用身份核查 → 可选批准文字反证 → 本地重新观察和修订 → 人工复核与导出**。

DGX Spark 的价值是把机构照片、视觉生成、方法执行、资料和案卷存储放在一个本地计算节点。GB10 统一内存支持本次视觉与独立文字、向量服务共存，CUDA 执行有实际运行记录。模型文件、资料与运行身份固定，既便于复现，也避免把敏感原图作为默认云端输入。统一内存仍需留出加载和共存余量，不能用模型文件大小替代运行内存。

## 三、优化方案与当前实现

| 问题 | 当前机制 | 验证边界 |
|---|---|---|
| 重复搜索或调用耗尽预算 | 有界协调器先读取本案、有限资料与首批照片；显示剩余预算 | 程序准备行为单独记录，不称模型自主发现所有 Skill |
| 输出过长、格式不合法 | LM Format Enforcer 结构约束、可选短动作协议、宿主再校验 | 控制格式和传输；不证明专业理由充分或整案提速 |
| 快速输入筛查 | 本地规则先比较六个维度，显示下一项补证 | 明确公式与未知项；不输出未经校准的真品率 |
| 引用不可追溯 | 固定正文版本、成功读取回执、NAT 身份核查 | 来源身份与是否支持判断分别检查 |
| 修订后旧依据复活 | 材料 epoch、案卷 revision、原件哈希和资格失效规则 | 编辑后恢复原值也不能恢复旧模型依据 |
| 等待模型和报告超时 | 单进程 / 单并发模型、每轮预算、单次期限、截断与失败状态 | 保留失败及消耗；不把晚到响应记为已收到的报告 |
| 探索更快推理及检索 | 部署独立 NIM、TensorRT-LLM 与 NVIDIA Embedding＋cuVS | 以固定模型、资料、预算进一步比较后再切换生产 |

## 四、成果与复现证据

公开体验预置三套完整教学案卷，无需用户先上传材料，支持真实编辑、区域定位、资料阅读、补证比较、复核备注和离线导出。馆藏照片来自 Met Open Access；项目教学记录与馆方基本资料分开标注，静态公开体验不发模型请求。真实 Spark 多图研究、StepFun 文字审查及本地修订另有独立归档。[完整体验](https://dingyucanada.github.io/cizheng-agent-skills/demo.html) · [真实案例与原件](https://dingyucanada.github.io/cizheng-agent-skills/report.html#actual-case)

2026-09-29 的安全只读记录显示五项服务健康均为 HTTP 200，主后端 0.7.0 配置 Qwen3-VL-8B 与 StepFun `step-3.7-flash`。新版软件完成本机 1120 项工程回归、37 项浏览器检查、Spark 54 项定向合同检查；公开馆藏原图真实 HTTP 上传与回取逐字节一致。工程检查证明权限、版本、格式与运行行为，不将数量计作专家器物样本。[部署及软件记录](../verification/software/v09/README.md)

NIM、TensorRT-LLM 与独立检索分别保存实际接口、模型 / 软件身份、公开输入、响应或数值核验以及 GPU 证据，范围见[技术栈](technology-stack.md)。独立专家样本评价、观察与引用支持质量、同预算 Skills 对照及整案延迟分布是后续验证重点。FLARE 联合训练、NeMo RL 后训练、智能眼镜厂商接入与博物馆桌面采集箱作为研究路线，当前不宣称已部署或制造。
